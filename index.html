1. 공통 원칙

ODDDAY는 서비스 제공에 필요한 범위에서만 정보를 처리합니다. 이용자의 기기에만 남는 기록과 서버·외부 서비스로 전송되는 정보는 서비스마다 다르므로 별도로 명시합니다. 개인정보 및 민감정보의 접근, 수집, 이용, 제공, 보관, 삭제 방식과 관련 외부 서비스는 각 서비스 설명을 확인해 주세요.

정보를 외부 서비스로 전송하는 기능이 추가되는 경우, 해당 목적과 처리 방식을 반영하여 방침을 변경하고 필요한 안내·동의를 진행합니다. 이 정책에 아직 기술되지 않은 앱에 대해서는 서비스별 개인정보 처리 사실이 확인되기 전까지 이 페이지를 완결된 고지로 간주할 수 없습니다.

2. DAY.zip — 디데이·기념일·유통기한

적용 대상: DAY.zip Android 앱 및 웹 버전 · 현재 공개된 앱 기능을 기준으로 작성

2.1 기기에 저장하는 정보 및 목적

입력한 날짜, 제목, 메모, 카드 색상, 순서, 언어 및 꾸미기 설정은 사용 중인 기기의 앱 또는 브라우저 저장 공간에 보관합니다. 디데이 목록 표시, 정렬, 테마 설정과 홈 화면 위젯 표시를 위해 사용합니다. 이러한 기록을 개발자 서버로 전송하거나 서버에 동기화하는 기능은 없습니다. 회원가입이나 로그인을 요구하지 않습니다.

2.2 Android 앱의 데이터 및 권한 처리

현재 공개된 정책 기준 Android 앱은 화면과 기능을 앱 안에 포함하며 인터넷 연결 권한, 광고 SDK 또는 이용 분석 SDK를 사용하지 않습니다. 카메라, 위치, 연락처, 사진 또는 전체 파일 접근 권한을 요구하지 않습니다. 백업 파일을 저장하거나 불러올 때 사용자가 직접 지정한 파일만 시스템 파일 선택기를 통해 접근합니다. 시스템 자동 앱 데이터 백업은 비활성화되어 있습니다.

홈 화면 위젯 표시를 위해 날짜 기록의 사본과 사용자가 선택한 표시 설정을 기기 안에 저장합니다. 위젯에는 선택한 제목과 일수가 나타납니다. 알림창 표시 기능은 현재 제공하지 않고 알림 권한도 요청하지 않습니다. 기기 재시작이나 날짜·시간대 변경 시 위젯 표시를 갱신합니다.

2.3 웹 버전과 외부 호스팅

웹 버전은 화면 및 설치 파일을 호스팅 제공자로부터 받아 실행합니다. 이 과정에서 호스팅 제공자의 접속 및 보안 정책에 따라 기술적인 접속 정보가 처리될 수 있습니다. 웹 버전은 날짜 기록을 개발자 서버에 동기화하지 않으며 광고·이용 분석 도구를 사용하지 않습니다. 웹과 Android 앱의 로컬 기록은 서로 자동으로 연동되지 않습니다.

2.4 보관·보안 및 삭제

기기 안의 기록은 이용자가 삭제하거나 앱·브라우저의 저장 데이터를 지우기 전까지 로컬 저장 공간에 남습니다. Android 앱에서 기록을 삭제하거나 기기 설정에서 앱 데이터를 삭제할 수 있습니다. 웹 버전은 브라우저의 해당 사이트 데이터를 삭제하면 기록을 제거할 수 있습니다.

내보낸 백업 파일에는 날짜, 메모 및 설정이 포함될 수 있습니다. 파일은 사용자가 직접 선택한 위치에 저장되며 별도의 암호화 없이 저장됩니다. 클라우드 저장 위치를 고르면 해당 서비스의 정책이 적용됩니다. 내보낸 파일은 앱의 기록을 삭제하더라도 자동 삭제되지 않으므로 이용자가 별도로 삭제해야 합니다.

기기 자체의 접근 통제, 저장 공간 및 백업 파일의 관리는 이용 중인 기기와 선택한 저장 서비스의 보안 설정에도 영향을 받습니다.

광고 관련 안내: DAY.zip의 비공개 테스트 중인 현재 버전에는 광고 SDK가 적용되어 있지 않습니다. 향후 Google AdMob 광고 또는 이용 분석 기능을 실제 도입하는 경우, SDK가 처리하는 데이터·제3자 제공·목적과 필요한 동의 절차를 확인하여 시행 전에 본 방침 및 앱의 데이터 보안 신고 내용을 변경합니다.

3. Rough-log — 기록과 일기

3.1 처리하는 정보와 목적

익명 또는 Google 로그인 시 서비스 계정 식별자, Google 계정이 제공한 이메일·이름 등 인증 정보와 로그인 세션을 계정 식별 및 기기 간 동기화에 사용합니다. 이용자가 입력한 원문, 수정 이력, 사건·거래 정보, AI 분석 결과, 일기·Best·회고와 사용자 수정본을 기록 표시·통계·일기 및 회고 작성에 사용합니다. 입력 내용에 사람·장소·소비·기분·운동 등 개인적인 정보가 포함될 수 있습니다. 프로필·설정은 서비스 이용 환경 유지에, AI 호출·토큰 사용량은 처리 상태 및 호출 제한 관리에 사용합니다.

이용자가 선택한 하루 대표 사진은 기기 간 표시를 위해 Supabase의 비공개 저장소에 저장합니다. 브라우저에서 크기를 줄이고 서버에서 EXIF·GPS 등 메타데이터를 제거하며, 원본 파일은 저장하지 않습니다. 사진은 AI 분석에 사용하거나 AI 제공자에게 전송하지 않습니다. 사진에 직접 보이는 개인정보는 사진 내용에 남을 수 있습니다.

AI 작업 종류·처리 시각·상태·토큰 사용량과 서버 오류 코드를 처리 상태·호출 제한·장애 대응에 사용합니다. 검색어는 현재 앱에서 별도의 검색 기록으로 서버에 저장하지 않습니다. 광고 ID 등 기기 고유 식별자를 수집하는 광고·분석 SDK는 현재 앱 코드에 포함하지 않습니다. 인증·호스팅 제공자는 서비스 운영을 위해 IP·사용자 에이전트 등 접속 정보를 처리할 수 있습니다.

3.2 외부 서비스

Google OAuth는 로그인, Supabase는 인증·데이터베이스·비공개 사진 저장 및 서버 처리, Vercel은 웹 호스팅에 사용합니다. AI 분석·일기·회고를 요청하면 필요한 기록 및 정리된 정보를 OpenAI API로 전송합니다. 현재 생성 요청에는 store:false를 사용하지만 이것이 제공자의 모든 기술 로그나 백업이 즉시 삭제된다는 뜻은 아닙니다. 본 안내 페이지는 GitHub Pages에서 제공합니다. 이메일 문의는 Gmail로 받습니다.

각 제공자의 정확한 보관 기간, 처리 지역 및 국외 이전 관련 계약·고지 항목은 운영자가 추가 확인 중입니다. 확인하지 않은 국가·기간·법적 의무를 확정 사실로 안내하지 않습니다.

3.3 계정 삭제와 데이터 삭제

계정 삭제는 Rough-log 계정과 프로필·설정·관련 기록을 함께 삭제합니다. 데이터 삭제는 계정·Google 로그인·프로필·설정을 유지하면서 선택한 날짜의 관련 기록 또는 모든 기록을 삭제합니다. 두 경우 모두 Google 계정 자체는 삭제하지 않습니다.

계정 삭제 요청데이터 삭제 요청

두 안내 페이지에서 앱 내 경로와 로그인 없이 이메일로 요청하는 방법을 확인할 수 있습니다. 설정의 계정 관리 또는 데이터 관리에서 직접 삭제할 수 있으며, 로그인할 수 없으면 이메일로 요청해 주세요. 이메일 주소만으로 삭제하지 않으며 기존 계정의 검증된 메일함을 통한 별도 소유 확인을 진행합니다.

3.4 보관 및 삭제

서비스 계정과 기록은 이용자가 삭제하기 전까지 기능 제공을 위해 보관합니다. 데이터만 삭제하면 계정·프로필·설정과 로그인 연결은 유지합니다. 날짜별·전체 데이터 삭제 및 계정 삭제에는 해당 범위의 사진 파일과 연결 정보도 포함됩니다. 사진은 오늘 또는 달력에서 개별 삭제할 수도 있습니다. 완료된 서버 삭제 작업에서는 사용자 식별자·대상 목록을 제거하고, 최소 완료 확인 기록은 7일 후 일일 정리 작업에서 삭제합니다. 실패한 요청은 재처리 완료까지 최소 식별 정보와 상태를 보관합니다.

직접 내보낸 파일은 이용자가 별도로 삭제해야 합니다. 지원 이메일, 서비스 제공자의 백업·접속 및 보안 로그의 실제 보관·만료 기간과 별도 법적 보관 의무는 아직 확인 중입니다. 일률적인 이메일 요청 처리 기한도 확정되지 않았으며 접수 후 확인된 범위·일정·보관 예외를 안내합니다. 확인되지 않은 기간을 법정 의무로 표시하거나 즉시 완전 소거를 약속하지 않습니다.
